# Contributor instructions

Use only public, redistributable sources. Preserve upstream notices and record imported file provenance. Do not include legacy databases, commercial SQLite extensions, vendor branding, credentials, private text, local paths, account information, conversation transcripts, or private operational details in tracked files, commits, issues, and pull requests.

Keep public descriptions concise and technical. Use English present-tense commit subjects. State tested behavior and limitations accurately. Do not claim production readiness or identical legacy behavior without evidence.

Use the personal repository owner only. Repository identity and credentials are governed locally outside tracked content. Never change global Git/authentication configuration or access organization resources. Run `bash scripts/build.sh` before handoff; it includes isolated behavior tests. Do not install, register, replace, or activate an input method without explicit user authorization. Do not read personal dictionaries during ordinary tests.

Preserve the original upstream interaction logic and UI. Change behavior only for compatibility, license compliance, safety, or an explicitly approved issue.
